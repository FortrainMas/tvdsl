# HW3. Таблицы символов и проверка типов Funny

Проход по AST из HW2: проверяет имена и типы, записывает тип каждого выражения в дерево и собирает все ошибки с
позициями, не останавливаясь на первой. Бонус (вывод типов локальных переменных) сделан.

## Запуск

Из папки `hw3/`, нужен [uv](https://docs.astral.sh/uv/). `hw2` и `hw1` подключаются автоматически.

```bash
uv run hw3 tests/good/inference.funny
```

```bash
uv run hw3 tests/bad/types.funny
```

```bash
uv run hw3 test
```

- `hw3 файл.funny` — печатает аннотированный AST в JSON, а если есть ошибки, то список
  `файл:строка:столбец: сообщение` и код возврата 1. При синтаксических ошибках проверка типов не запускается.
- `test` — прогоняет `tests/good` (сравнивает дерево с эталоном `.json`) и `tests/bad` (сравнивает ошибки с `.txt`).

## Код

| Файл | Что делает |
|---|---|
| `src/hw3/checker.py` | таблицы символов, проверка типов, вывод типов локальных |
| `src/hw3/__init__.py` | запуск по файлу и `test` |
| `tests/good`, `tests/bad` | тестовые программы и ожидаемый результат |

## Типы

| Тип | Где бывает |
|---|---|
| `int` | переменные, параметры, результаты, выражения |
| `int[]` | переменные, параметры, результаты; массив одномерный |
| `bool` | только условия и предикаты; переменных этого типа нет |

Приведений и перегрузок нет: типы должны совпадать точно.

## Правила для выражений

| Выражение | Операнды | Результат |
|---|---|---|
| `5` | | `int` |
| `true`, `false` | | `bool` |
| `x` | | тип переменной |
| `-e` | `int` | `int` |
| `a + b`, `-`, `*`, `/` | `int`, `int` | `int` |
| `a == b`, `!=`, `<`, `<=`, `>`, `>=` | `int`, `int` | `bool` |
| `a and b`, `or`, `->` | `bool`, `bool` | `bool` |
| `not e` | `bool` | `bool` |
| `a[i]` | `int[]`, `int` | `int` |
| `length(a)` | `int[]` | `int` |
| `f(...)` | по сигнатуре | тип результата, если он один |
| `formula(...)` | по сигнатуре | `bool`, только в предикатах |
| `forall`, `exists` | тело `bool` | `bool`, только в предикатах |

## Правила для операторов

- `if`, `while`: условие `bool`.
- `requires`, `ensures`, `invariant`, `assert`, `assume`, тело формулы: `bool`. Только здесь можно использовать формулы
  и кванторы.
- `x = e`: тип `e` совпадает с типом `x`, `bool` присвоить нельзя.
- `x, y = f(...)`: число переменных равно числу результатов `f`, типы совпадают попарно.
- `a[i] = v` (в дереве это `a = set(a, i, v)` с `sugar: true`): `a` — `int[]`, `i` и `v` — `int`.
- В параметры (и в параметры-массивы) писать нельзя.
- Функция с несколькими результатами допустима только справа в `x, y = f(...)`, в выражении нельзя.

## Таблицы символов

- **Функции и формулы** лежат в одной общей таблице, которая заполняется до проверки тел. Поэтому работают рекурсия и
  вызов функции, объявленной ниже. Имена не повторяются.
- **Переменные** лежат в стеке областей `scopes`: область функции и по одной области на каждый квантор.
- Блоки `{}` своей области не создают: по спецификации локальные переменные уникальны в пределах функции.
- Переменная может называться как функция, это разные таблицы: `add(add, 1)` допустимо.
- Имена параметров, результатов, `uses` и переменной квантора не должны повторять уже видимые имена.

**Что где видно:** правила получаются сами, потому что имена объявляются в том же порядке, что и в тексте функции.

| Где | Видно |
|---|---|
| `requires` | параметры |
| `ensures` | параметры, результаты |
| тело, `invariant`, `assert`, `assume` | параметры, результаты, `uses` и локальные, которым уже было присваивание выше по тексту |

## Вывод типов локальных (бонус)

Локальная переменная объявляется через `uses` (с типом или без) либо первым присваиванием. В `locals` аннотированного
дерева выведенные типы помечены `"inferred": true`.

| Откуда тип | Пример | Результат |
|---|---|---|
| первое присваивание | `t = 1;` | `t: int` |
| обновление массива | `uses a; a[0] = 42;` | `a: int[]` |
| контекст | `uses t; r = t + 1;` | `t: int` |
| ожидаемый тип аргумента | `uses a; r = length(a);` | `a: int[]` |

Ошибки:

- противоречие: `t = 1; t = a;`;
- переменная из `uses` без единого присваивания;
- чтение до присваивания, когда тип неоткуда взять: `uses t; u = t;`;
- `q[0] = 1;` без объявления `q`: это чтение несуществующего массива.

## Унификация

Сводится к сравнению типов, потому что сигнатуры всегда явные: неизвестным может быть только тип локальной переменной.
При первом ожидании такая переменная получает ожидаемый тип, дальше типы сравниваются точно. После уже показанной
ошибки у выражения внутренний тип `?`: он совместим с чем угодно, поэтому одна ошибка не тянет за собой другие. В
результат `?` не попадает, потому что при ошибках дерево не печатается.

## Аннотированный AST

Дерево HW2, в котором добавлено:

- `type` у каждого выражения: `"int"`, `"int[]"` или `"bool"`. У вызова функции с несколькими результатами это список,
  например `["int", "int[]"]`;
- `locals` у каждой функции: все локальные с итоговыми типами, например
  `[{"name": "i", "type": "int", "inferred": true}]`. Поле `inferred` равно `true`, если тип выведен, и `false`, если
  он указан в `uses`;
- `line` и `col` у всех узлов, кроме `program`.

## Ошибки

Формат `строка:столбец: сообщение`, ошибки отсортированы по позиции. Позиция — переменная или операнд с неверным типом,
начало оператора при неверном присваивании, объявление при повторном имени.

```
tests/bad/types.funny:2:9: оператор +: ожидался int, а получен int[]
tests/bad/calls.funny:13:5: слева переменных: 2, а one возвращает значений: 1
tests/bad/step05_bad_modify_param.funny:2:5: параметр x только для чтения
```

## Ограничения и отклонения

1. **Пример `step05_good_while_nested` из курса считается ошибкой.** В нём есть `n = n - 1`, где `n` — параметр.
   Спецификация это запрещает, и ровно то же самое делает `step05_bad_modify_param`.
2. **`a[i][j] = v` — ошибка типов.** Спецификация приводит такой пример обессахаривания, но типа «массив массивов» в
   языке нет: `a[i]` — это `int`.
3. **Анализа потока нет.**
   - Чтение объявленной переменной до присваивания не ошибка, если тип известен: по спецификации значение просто
     не определено.
   - Не проверяется, что всем результатам функции что-то присвоено.
   - Присваивание в одной ветке `if` объявляет переменную и для кода ниже.
4. **`invariant` видит только то, что присвоено выше цикла или объявлено в `uses`.** Локальную, которая появляется
   только в теле цикла, он не видит.
5. Диапазон `int` (32 бита) не проверяется, деление на ноль и выход за границы — ошибки времени выполнения.

**Изменения в HW2:** в узлы AST добавлены `line` и `col`, а в вызов `set` из сахара — `sugar: true`. Структура дерева
не изменилась, это проверено на всех эталонах, эталоны перегенерированы.

# HW1. Лексер: регулярное выражение → ДКА → минимизация

Python 3.12, без библиотек: регулярки → НКА (Томпсон) → ДКА (построение подмножеств) → минимальный ДКА (Хопкрофт).

## Запуск

Из папки `hw1/`, нужен [uv](https://docs.astral.sh/uv/):

```bash
uv run hw1 build
```

```bash
uv run hw1 test
```

```bash
uv run hw1 lex program.funny
```

```bash
uv run hw1 lex 'if (x <= 01) y = é;'
```

- `build` — строит автоматы, печатает размеры, сохраняет таблицы в `out/dfa.json` (до минимизации) и `out/dfa_min.json`.
- `test` — прогоняет `tests.json` и все 128 ASCII-символов через оба ДКА, печатает PASS/FAIL, пишет `out/test_results.json`.
- `lex` — разбивает на токены файл (если такой файл есть) или саму строку по сохранённой таблице `out/dfa_min.json`.

## Отчёт

**Регулярные выражения** (порядок = приоритет при одинаковой длине, поэтому ключевые слова выше `IDENT`):

| Токен | Регулярка |
|---|---|
| `WS` (пропуск) | `[ \t\r\n]+` |
| `COMMENT` (пропуск) | `//[^\n]*` |
| `KW_FUNCTION`, `KW_IF`, … | `function returns requires ensures uses int if else while invariant assert assume length true false not and or forall exists` |
| `IDENT` | `[A-Za-z_][A-Za-z0-9_]*` |
| `INT` | `0\|[1-9][0-9]*` |
| `BAD_INT` (ошибка) | `0[0-9]+` — чтобы `01` было ошибкой, а не `0` и `1` |
| операторы | `==` `!=` `<=` `>=` `->` `=>` `<` `>` `=` `+` `-` `*` `/` |
| разделители | `(` `)` `[` `]` `{` `}` `,` `;` `:` `\|` |

**Размеры:**

| Автомат | Состояний |
|---|---:|
| НКА | 350 |
| ДКА до минимизации | 126 |
| ДКА после минимизации | **123** |

Минимизация склеила 3 пары: `IDENT` после `A` и после `A0`, `INT` после `1` и после `10`, `COMMENT` после `//` и после
`//x`. Остальные состояния различимы, потому что ведут к разным токенам: в основном это префиксы ключевых слов.
Начальное разбиение в Хопкрофте строится по имени токена. Если делить только на «принимает / не принимает»,
автомат схлопывается до 12 состояний и путает токены.

**Ловушка:**

- Это пустое множество состояний НКА; в минимальном ДКА — состояние 1.
- Она не принимает, и все переходы из неё ведут в неё же.
- Туда попадают символы, с которых не начинается ни один токен (`@`, `#`, `"`, `.`, управляющие символы…), и любой
  символ вне ASCII.
- Лексер, попав в ловушку, берёт последний найденный токен (longest match). Если токена не было, выдаёт `ERROR` на один
  символ и идёт дальше.

**Тесты:** 189/189 PASS:

- 57 строк из `tests.json`;
- каждый из 128 ASCII-символов;
- 4 не-ASCII символа.

Покрыты обязательные сценарии задания:

- пустая строка, пробелы, табы, CRLF;
- `0`, `00`, `01`;
- `_` в идентификаторах;
- все ключевые слова и похожие на них идентификаторы (`iff`, `lengthy`);
- все операторы и разделители;
- комментарии;
- не-ASCII (`é`, `→`, кириллица) — `ERROR`.

Каждая строка проверяется и на ДКА до минимизации, и после — результаты должны совпасть.

## Формат таблицы (`out/dfa_min.json`)

```json
{ "start": 0, "trap": 1, "accept": ["имя токена или null", ...], "transitions": [[следующее состояние по коду символа 0..127], ...] }
```

Символ с кодом ≥ 128 сразу ведёт в `trap`. В проекте таблицу можно подключить так:
`tokenize(load_json("out/dfa_min.json"), text)`.

## Что решил сам

- **Ключевые слова — объединение списков из HW1, P01 и грамматики Funny.** Добавлены `:` `|` `->` `=>`, без них
  грамматику не разобрать.
- **`_` в идентификаторах разрешён**, как в P01 и в примерах (`is_sorted`).
- **Алфавит строго ASCII,** как в задании. Поэтому русские комментарии и `→` из примеров проекта дают `ERROR`. Для
  проекта это надо будет решить отдельно.
